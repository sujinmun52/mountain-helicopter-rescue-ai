# RF Model 설계

> 모델의 전반적인 틀은 Random Forest (RF) 임.

## RF Model을 사용한 이유
랜덤 포레스트의 기본 뼈대인 Decision Tree는 데이터를 특정 기준값으로 쪼개나가는 방식으로 작동하는데, 인간이 설계한 위험도 수식의 논리 구조와 모델의 작동 메커니즘이 완벽하게 일치함. 선형 회귀처럼 부드러운 곡선을 그리며 예측하는 모델보다 딱 끊어지는 지형적 위험 경계선을 나타내는데 유리하기 때문

## 모델의 전반적인 흐름
1. csv 파일을 읽어와 하나의 리스트로 합치기
2. 정답 라벨링이 없는 데이터이므로 가설 설정에서 나눈 기준에 따라서 가중치, 점수를 부여해 정답 라벨(target) 부여
3. Train set / Test set 분리 (K-Means 사용)
 1. 위경도 좌표를 가져와 각각의 군집으로 묶기
 2. Test set으로 분리할 구역 설정
 3. Test set 구역과 Train set 구역의 모든 좌표 추출
 4. Train set 구역의 각각의 점들이 Test set 구역의 가장 가까운 점과 얼마나 떨어져있는지 거리 계산 (단위: 도)
 5. 0.001도 = 약 110m
 6. Test 구역 경계로부터 설정한 buffer_distance 거리보다 멀리 떨어져있는 데이터만 최종 Train set으로 확정
 7. 학습에 제외할 컬럼을 분리 (가설 설정, 정답에 영향을 준 컬럼은 분리)
4. RF Model 설계
 - 나무의 개수, 하나의 나무에서 파고들어갈 깊이, 학습을 중단할 지점 설정

## land_type의 불연속성 (즉, 범주형 데이터)

현재 2번과 3번 파일에서 land_type 컬럼을 다른 연속형 변수들과 함께 무조건 .astype(np.float32)로 변환하여 랜덤 포레스트에 밀어 넣고 있음.

문제점: 만약 land_type이 순서형(Ordinal)이 아닌 명목형(Nominal) 범주 데이터라면(예: 0=수풀, 1=암반, 2=계곡), 랜덤 포레스트는 이를 연속된 숫자로 오판함. 즉, 모델 내부에서 나무들이 "지형 종류가 0.5 이하인가?" 같은 비논리적인 기준으로 가지를 쳐서 억지 학습을 하게 됨,

방어 및 해결책: land_type이 숫자의 크기와 상관없는 순수 범주형 변수라면 원래 원-핫 인코딩(One-Hot Encoding)을 거쳐야 안전함.

만약 land_type의 숫자(0, 1, 2...)가 크기와 상관없는 단순한 지형의 종류라면, 모델이 이를 연속된 숫자로 오해하지 않도록 원-핫 인코딩(One-Hot Encoding)을 해줌.

이미 파이프라인이 3개 파일로 분리되어 있으므로, 1번 파일에서 가공하고 2, 3번 파일에서 이름만 바꿔주면 끝남. 즉 컬럼을 세 개로 나눠 각각을 이진 데이터(0, 1)로 분류함.
