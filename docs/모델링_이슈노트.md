## 1. [수정 완료] 경사도 과대 계산 → 보행 A* 항상 실패

- **증상**: 착륙지→조난자 보행 A*가 항상 실패하고 직선 폴백. 도보 ETA 60분/평균경사 53.9°(절벽) 등 비현실적.
- **원인**: 격자 셀 실제 간격은 **행 81m / 열 140m** 인데, `terrain.py`의 경사 계산이 셀 간격을 **15m로 하드코딩**(`DEM_RESOLUTION=15`). 고도차를 ~7배 짧은 거리로 나눠 경사가 폭증 → 완만한 비탈도 70°+ 절벽으로 계산 → `compute_rescuer_cost`의 `slope>45° → inf` 하드차단이 97% 셀을 막음.
- **수정**: `calculate_slope`에 실제 셀 간격(행/열 m)을 전달(`cell_m`). `main.py`에서 `dem_lats/lons`로 측정해 주입.
  - 결과: 경사 중앙값 73.2° → **23.7°**, 경사>45° 비율 97.1% → **0.2%**, 보행 A* **성공**, 도보 ETA 60분 → **5.4분**, 합계 ETA 66.6분 → **11.6분**.
  - 곡률/능선(`is_ridge`) 임계치(0.02)는 `resolution=15` 기준으로 튜닝돼 있어 **의도적으로 보존**(거동 일관성).

## 2. [재학습 필요] 모델이 풍속에 무반응 — 동적 기상이 모델에 안 들어감

- **증상**: 추론 시 풍속을 0→25 m/s로 바꿔도 모델 예측(안전/주의/위험) 분포가 **완전히 동일**.
- **원인 (두 겹)**:
  1. **학습 데이터가 약풍 3일치뿐**: `batch_runner.py` 기본값 `2025-10-01 ~ 10-03, 3h 간격, 24시점`. 그 기간 실제 풍속이 **0~4.9 m/s**(평균 1.54)에 불과. 6 m/s 이상은 학습 범위 밖(외삽) → 무반응.
  2. **라벨링이 기종 무관 + 약풍이라 풍속 영향 소멸**: `score_utils.compute_wind_score`는 `풍속<5 → 1.0(만점)`. 학습 풍속이 전부 <5라 **모든 샘플의 풍속 점수가 1.0으로 깔림** → 풍속이 라벨을 가르는 데 기여 못 함 → 모델이 "풍속 무관"으로 학습.
- **영향**: 프로젝트 핵심 "동적 기상 반영"이 **모델 분류 단계에서는 작동 안 함**. 기상은 뒤쪽 `risk_score` 룰기반 후처리(`compute_wind_score`)에서만 반영됨.
- **필요 조치 (재학습)**:
  - 강풍 포함 기간으로 batch 재생성(약풍↔강풍 교체로 풍속 0~25 다양성 확보).
  - 라벨링 풍속 임계를 **기종별**로 분리(아래 4번 규정 반영: 소형 10 / 대형 20).
  - 데이터 과다(3,600만 행) → **공간 다운샘플(격자 15~20%)** 로 학습량 1/5~1/7 축소 권장.

## 3. [추론단 방어 필요] `static_score_*` 컬럼 45% nan

- **증상**: `terrain_base.parquet`의 `static_score_large_landing/hoist` 등 **45.2%가 nan**.
- **위험**: 반경 내 후보가 전부 nan zone이면 `infer_best_zone`의 `risk_score=nan`이 파이프라인에 전파될 수 있음(현재는 우연히 정상값이 뽑힘).
- **조치**: 추론 시 nan static_score 후보를 제외하거나 기본값 처리(방어코드). 근본적으로는 전처리(`1.xgb_preprocess.py`/`terrain_base.py`)에서 nan 발생 원인 점검.

## 4. [수정 완료] 풍속 제한이 기종별로 달라야 함 (구: 단일 15)

- **규정 출처** (※ 정확한 문서/기관명 확인 필요 — 주석에 박을 예정):

  | 구분 | 초대형 | 대형 | 중형 | 소형 |
  |------|--------|------|------|------|
  | 최대풍속 | 20 m/s | 20 m/s | 15 m/s | 10 m/s |

  - 단서: "기종별 비행교범 세부 제한치를 초과할 수 없으며 **현장의 기장 판단을 우선**", "긴급 운항 시 **조종사 판단 하에** 「항공안전법 시행규칙 제175조 별표24」 준용 가능".
- **현재 코드 문제**: `WIND_BLOCK = 15.0` **단일값**.
  - 대형: 20이어야 하는데 15 → 과보수(갈 수 있는 곳 차단)
  - 소형: 10이어야 하는데 15 → 과관대(위험 허용)
- **수정 완료 (3곳 일관 적용, 2026-06-09)**:
  1. `config.py` — `HELI_WIND_LIMIT = {"light":10.0, "heavy":20.0}` 추가(출처 주석 포함), `WIND_BLOCK=15.0`은 폴백으로 유지.
  2. `modules/pathfinding.py` — `compute_helicopter_cost`가 `size`별 제한 적용 + `_a_star_helicopter_core` 비상회랑 base도 기종별.
  3. `modules/evaluation/metrics.py` — `evaluate_path(size=...)`로 기종별 위험풍속 판정. `main.py` 호출부에 `size=heli_size` 전달.
- **검증**: 파이프라인 완주, 평가 출력 `위험풍속 구간 비율(>20m/s)`(대형 기준) 확인. 약풍이라 실제 차단은 미발생.
- **남은 과제 (이번 범위 외)**: hard block 유지 선택함. "긴급 시 기장 판단 준용"(soft+경고)을 살리려면 `main.py`를
  레거시 `A_star_helicopter` → `A_star_helicopter_safe`(비상회랑 escalation)로 전환 필요. escalation 단계의
  `WIND_BLOCK+3/+5`도 기종별 base 기준으로 정리 권장(현재 미사용).
